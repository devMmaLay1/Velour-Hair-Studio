1. Project goal

Turn the salon website into a complete branded store experience where users can browse salon products, filter by category, open a product page, add items to cart, review cart contents, complete checkout, pay, and land on a successful order confirmation page.

Main objective: make the ecommerce side feel intentional, premium, and fully connected to the Velour brand instead of feeling like one isolated shop screen.

3. User journey

Step 1: User lands on Shop and sees premium product cards.
Step 2: User filters or searches products by category, price, or product name.
Step 3: User opens a product detail page to see full information.
Step 4: User selects quantity and variant, then adds to cart.
Step 5: User reviews the cart and adjusts quantities.
Step 6: User proceeds to checkout, fills delivery details, and pays.
Step 7: User lands on order success page and can continue shopping.

4. Page-by-page implementation plan

4.1 Shop page

Purpose: main product discovery page.

  • Hero section with store intro and short salon retail message
  • Category filter tabs
  • Search bar
  • Sort dropdown: newest, price low to high, price high to low, featured
  • Product grid with image, name, category, price, badge, add-to-cart button
  • Empty state when no products match filter
  • Cart icon with live cart count

Required on day one

4.2 Product details page

Purpose: full product information and confident conversion.

  • Main product image and thumbnail gallery
  • Product title, price, short description, long description
  • Variant selector for size, bundle, or version
  • Quantity stepper
  • Add-to-cart button
  • Stock status
  • Benefits section: use case, texture match, hair benefit
  • Related products section

Required on day one

4.3 Cart page or cart drawer

Purpose: let users review and update order before payment.

  • List all cart items
  • Show image, title, selected variant, single price, quantity, total
  • Increase or decrease quantity
  • Remove item
  • Subtotal display
  • Checkout button
  • Continue shopping button

Required on day one

4.4 Checkout page

Purpose: collect order info and handle payment.

  • Customer name
  • Email
  • Phone number
  • Address
  • City / state
  • Delivery note or pickup note
  • Order summary card
  • Paystack pay button
  • Validation before payment

Required on day one

4.5 Order success page

Purpose: confirm payment and complete the flow.

  • Thank-you message
  • Order reference
  • Product summary
  • Delivery expectation message
  • Continue shopping button

Required on day one

4.6 Optional next layer

Purpose: improve experience after base ecommerce works.

  • Wishlist
  • Promo code support
  • Customer reviews
  • Inventory warnings
  • Bundle products
  • Upsell on cart and checkout

Build after core flow is stable

6. Data model plan

All pages should use one product data source so the store stays consistent.

Product object fields

  • id
  • slug
  • name
  • category
  • price
  • oldPrice
  • badge
  • description
  • longDescription
  • image
  • gallery
  • stock
  • featured
  • variants

Cart item fields

  • id
  • slug
  • name
  • price
  • image
  • variant
  • quantity

Important rule

Do not hardcode separate versions of the same product across shop, product, and cart pages. One source of truth should feed everything.

7. Build phases

1

Foundation

  • Create product data file
  • Decide store categories
  • Prepare all product images
  • Create shared cart helper functions
  • Set up localStorage cart key
2

Shop page completion

  • Render product cards from JavaScript data
  • Add category filters
  • Add search
  • Add sorting
  • Connect add-to-cart button
  • Show cart count in navbar or shop header
3

Product page completion

  • Use product slug or query string to load correct product
  • Render gallery and details dynamically
  • Handle variants and quantity
  • Connect add-to-cart from product page
  • Show related products
4

Cart system

  • Create cart page or drawer
  • Render line items from localStorage
  • Update quantities
  • Remove products
  • Calculate subtotal in real time
5

Checkout system

  • Create validated checkout form
  • Render final order summary
  • Connect Paystack
  • Store temporary order data before redirect
  • Handle success callback cleanly
6

Success and polish

  • Create order-success page
  • Show confirmation details
  • Clear cart after successful payment
  • Add premium empty states and error states
  • Test mobile responsiveness on all store pages

8. Core implementation rules

  • Build the full buying flow before adding fancy extras
  • Make product rendering dynamic, not manually repeated in HTML
  • Keep cart state shared across all ecommerce pages
  • Keep styling premium and consistent with the salon brand
  • Test every action on mobile first

9. What to avoid

  • Do not build only the shop grid without a real cart system
  • Do not hardcode product content on multiple pages separately
  • Do not connect payment before checkout validation works
  • Do not add wishlist, coupons, or reviews before core flow is done

10. Definition of done

The ecommerce side can be called complete when all of these are true:

  • Shop page renders products dynamically
  • User can filter, search, and sort products
  • User can open a proper product details page
  • User can add products to cart from both shop and product page
  • Cart updates quantity and subtotal correctly
  • Checkout collects valid customer data
  • Paystack opens with the right amount
  • Order success page works and clears cart
  • The full flow works on mobile and desktop
